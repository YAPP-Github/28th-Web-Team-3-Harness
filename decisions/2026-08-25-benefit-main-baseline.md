# 혜택 main 구현 기준 기록

- 날짜: 2026-08-25
- 상태: accepted
- 관련 정책과 플로우: [POLICY-BENEFIT-001](../domain/policies/benefit-001-discovery-and-bookmark.md), [FLOW-BENEFIT-001](../domain/workflows/benefit-001-browse-and-bookmark.md)

## 배경

혜택 구현이 완료된 뒤 운영·개선 작업의 출발점으로 사용할 공통 정책이 필요해 FE와 BE의 같은 시점 `main` 구현을 역문서화했다. 과거 `codex/docs-mypage-benefits` 브랜치 문서와 Figma 시안은 현재 구현의 근거로 사용하지 않았다.

- BE: `6deb8af2f5e167cbbaf0d15ce9a025cf7c7a6227`

## 조사 범위

- FE 혜택·저장됨 페이지와 정책·절약 팁 탭, 필터, 카드, 저장 큐, 저장 취소 확인 컴포넌트
- FE 정책·절약 팁·저장 목록 API 계약과 스키마, 목록·카드·저장 상태 테스트
- BE 정책·절약 팁·저장 목록 컨트롤러와 응답 계약
- BE 정책 노출 범위·조회, 절약 팁 조회, 북마크 서비스와 도메인, 인수 테스트

## 결정

- FE는 사용자가 보는 탭·필터·빈 상태·오류 복구·외부 이동·저장 취소 확인의 기준으로 사용한다.
- BE는 정책 노출 범위, 프로필 조건, 정렬, 콘텐츠 존재 검증, 게스트별 저장과 멱등성의 기준으로 사용한다.
- 정책 혜택과 절약 팁은 하나의 혜택 화면 및 저장됨 화면을 공유하지만 분류 체계와 목록 조회 방식은 서로 독립된 정책으로 기록한다.
- 목록 응답에 전체 개수가 없으므로 정책 혜택은 페이지를 이어 조회하고 총개수를 정책으로 확정하지 않는다. 절약 팁과 저장된 절약 팁은 현재 화면 구현대로 모든 페이지를 모아 표시한다.
- 연속 저장 입력에서는 마지막 사용자 의도를 보존하고, 저장 실패 시 확인된 서버 상태로 복구하는 사용자 관찰 동작만 공통 규칙으로 채택한다. 캐시·상태 관리 라이브러리 세부사항은 제외한다.

## 구현 차이와 운영 주의사항

- BE 저장 목록의 정책 `category`는 원본 `largeCategory`를 반환하지만 일반 정책 목록·상세의 `category`는 `금융`, `주거`, `교육`, `복지`로 정규화된 값이다. FE 저장된 정책 카드는 저장 목록의 `category`를 쓰지 않고 상세 또는 기존 목록에서 얻은 정규화 분류를 사용한다. 저장 목록의 카테고리 필터 의미를 정규화 4분류로 추론하지 않는다.
- BE는 저장 목록에 `POLICY`와 `TIP`을 함께 제공할 수 있다. FE 저장된 정책은 `POLICY` 목록을 조회하지만 저장된 절약 팁은 통합 저장 목록 대신 전체 팁의 `bookmarked` 값을 기준으로 고른다.
- 저장된 정책의 저장 취소에는 확인 단계가 있지만 저장된 절약 팁에는 확인 단계가 없다. 두 흐름을 같은 확인 정책으로 합치지 않는다.
- 저장된 정책은 저장 최신순이지만 저장된 절약 팁은 전체 팁 목록을 등록 순으로 조회한 뒤 저장 여부로 거른다. 저장됨 화면 전체가 같은 정렬을 쓴다고 가정하지 않는다.
- 일반 절약 팁 목록이 비었을 때 FE는 별도 빈 상태 문구를 제공하지 않는다. 이는 현재 구현 상태이며 빈 상태 문구를 새 정책으로 추론하지 않는다.
- BE 저장 목록의 카테고리 필터는 정책에서 원본 대분류, 팁에서 팁 카테고리를 대상으로 부분 일치한다. 현재 FE는 이 필터를 사용하지 않는다.
- BE 일반 정책 동기화는 현재 응답에서 범위를 벗어나거나 마감된 정책을 건너뛰지만 기존 저장 행을 정리하지 않는다. 교체 업로드가 아닌 일반 동기화만 사용하면 이후 마감된 정책이 조회 목록에 남을 수 있다.
- FE는 정책 저장 취소 전이나 처리 중 시작한 저장 목록 조회가 늦게 완료돼도 성공한 취소 결과를 덮어 카드가 다시 나타나지 않게 한다.
- FE 정책 저장 큐는 요청 전 대기 중인 변경을 화면 이탈 시 전송하지만, 요청 진행 중 추가 입력 뒤 즉시 이탈하면 추가 입력을 이어 보내지 못할 수 있다. 화면이 유지되는 동안의 마지막 입력 수렴과 화면 이탈 시의 마지막 입력 보장을 같은 불변조건으로 취급하지 않는다.

## 영향

혜택 개선 작업은 정규화 정책 분류와 저장 목록의 원본 대분류를 구분해야 한다. 저장 목록 계약이나 취소 확인을 통합하려면 FE와 BE를 함께 바꾸고 이 정책과 플로우를 갱신해야 한다.

## 검토한 대안

- 과거 미병합 혜택 문서를 최신 기준으로 사용: 고정 `main` 이후 변경과 구현 차이를 반영하지 못하므로 제외했다.
- Figma 시안을 정책 기준으로 사용: 완료된 구현과 다른 필터·문구가 있어 제외했다.
- BE 저장 목록의 정책 분류를 정규화 4분류로 간주: 실제 반환 필드가 원본 대분류이므로 제외했다.

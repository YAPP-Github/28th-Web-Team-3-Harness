# API Field Documentation

## 목적

이 스킬은 Swagger/OpenAPI를 복제하지 않는다. 클라이언트와 기획이 같은 의미로 사용할 수 있도록 API 필드의 **한국어 의미**, 사용 위치, 근거, 미확정 사항을 기록한다.

## 분석 기준

1. 대상 BE 저장소의 기준 브랜치와 커밋을 먼저 고정한다.
2. Swagger/OpenAPI 경로, `@Operation`/`@Schema` 설명, 요청·응답 DTO를 확인한다.
3. 컨트롤러에서 실제 HTTP 경로·메서드·DTO 사용을 확인한다.
4. 서비스·도메인 모델·수용 테스트로 필드의 생성 규칙과 값 범위를 검증한다.
5. 같은 DTO가 여러 API에서 재사용되면 필드 의미는 한 번만 정의하고 사용 API를 모두 연결한다.

## 기록 규칙

- 필드마다 JSON 경로, 한국어 의미, 타입/값, 사용 API, 근거, 상태를 기록한다.
- `확정`은 코드 또는 Swagger 설명이 의미를 직접 뒷받침할 때만 사용한다.
- `사용자 확인 필요`는 코드로 값의 형태는 알 수 있지만 제품 용어·표시명·정책을 확정할 수 없을 때 사용한다.
- `미확정`은 추측으로 채우지 않는다. 질문과 확인에 필요한 자료를 함께 적는다.
- 영문 enum 값은 코드에 한국어 의미가 직접 없으면 번역을 확정하지 않는다.
- 인증 토큰, 개인 식별자, 실제 운영 URL, 로그의 민감 값은 문서에 기록하지 않는다.

## 산출물 구조

`domain/api-field-mappings/` 아래에 다음을 둔다.

- `README.md`: 기준 커밋, 범위, 상태 정의, 전체 인벤토리
- `<api-domain>.md`: API 영역별 확정 필드 매핑
- `open-questions.md`: 확인 전에는 문서에 넣지 못하는 항목과 질문

## 완료 기준

각 API 영역은 다음을 만족해야 완료로 표시한다.

1. Swagger 경로와 실제 컨트롤러 경로가 대조되었다.
2. request, response, path/query parameter의 필드가 모두 분류되었다.
3. 모든 한국어 의미에는 근거 또는 사용자 확인 기록이 있다.
4. 미확정 항목은 빈칸이나 추측이 아니라 질문 목록으로 이동했다.

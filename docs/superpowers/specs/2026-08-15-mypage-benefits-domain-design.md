# 마이페이지·혜택 도메인 문서 설계

## 목표

FE와 BE가 마이페이지와 혜택 화면의 현재 사용자 동작을 같은 용어와 규칙으로 해석할 수 있게 공통 정책과 플로우를 기록한다.

## 기준

- 정책 기준: `YAPP-Github/28th-Web-Team-3-FE`의 `origin/develop` 커밋 `0386b29c95a28be493425418bfa754ebbf47a518`
- 마이페이지 화면 참고: Figma `WNPFcxA9sEnAMrTVMRVfjm`, 노드 `2256:21562`
- 혜택 화면 참고: Figma `WNPFcxA9sEnAMrTVMRVfjm`, 노드 `1876:22288`
- 코드와 Figma가 다르면 현재 정책인 FE `origin/develop` 동작을 따른다.

## 문서 구성

- `POLICY-MYPAGE-001`: 약관, 개인정보처리방침, 문의, 앱 버전, 탈퇴 규칙
- `FLOW-MYPAGE-001`: 문의와 탈퇴의 사용자 흐름 및 실패 처리
- `POLICY-BENEFIT-001`: 혜택 조회, 분류, 저장, 공식 신청 페이지 이동 규칙
- `FLOW-BENEFIT-001`: 필터 선택, 추가 조회, 저장 변경, 신청 페이지 이동 흐름
- `domain/glossary.md`: 마이페이지와 혜택에서 공유할 핵심 용어

## 불일치 처리

- Figma의 마이페이지 `내 정보` 항목은 FE `origin/develop`에 없으므로 현재 정책에 포함하지 않는다.
- Figma의 혜택 필터 `AI 추천·식비·교통·생활` 대신 FE의 `전체·저장·금융·주거·복지·교육`을 기록한다.
- Figma의 `15개 보러가기` 대신 전체 개수를 제공하지 않는 현재 API에 맞춰 개수를 정책으로 확정하지 않는다.
- Figma 카드의 제목과 설명은 예시 콘텐츠로 보고 고정 정책 데이터로 기록하지 않는다.

## 범위 경계

- FE 컴포넌트, 라우팅, 캐시 라이브러리 같은 기술 구현은 기록하지 않는다.
- 실제 URL, 시크릿, 인증 정보는 기록하지 않는다.
- 기존 미션 정책과 플로우는 변경하지 않는다.
- 현재 문서만으로 설명되는 화면별 오류는 각 정책과 플로우에 기록하며 `domain/exceptions.md`에는 중복 추가하지 않는다.

## 완료 조건

- 새 정책·플로우가 Harness 템플릿 섹션을 모두 포함한다.
- ID, 파일명, 상대 링크가 `AGENTS.md` 규칙을 만족한다.
- 새 용어가 한 문장 정의와 관련 정책 링크를 갖는다.
- 문서 내용이 FE 기준 SHA와 두 Figma 화면의 의도를 함께 반영한다.

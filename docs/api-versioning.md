# API 버전과 호환성 관리

이 문서는 운영 환경에 함께 배포되는 FE와 BE 조합의 호환성 근거를 관리한다. 같은 메이저·마이너 번호만으로 호환된다고 추정하지 않는다.

## 현재 기준

2026-08-29에 다음 저장소 상태를 확인했다.

- FE는 `v1.0.0`부터 `v1.1.8`까지 Git 태그를 사용한다. 패키지의 `0.0.0` 버전은 배포 호환성 식별자로 사용하지 않는다.
- BE에는 SemVer 형식의 Git 릴리스 태그가 없다. Gradle의 `0.0.1-SNAPSHOT`은 배포 호환성 식별자로 사용하지 않는다.
- `/api/v2/onboarding`, `/api/v2/goal` 같은 경로 버전은 해당 API 계약의 버전이다. BE 애플리케이션 릴리스 버전과 같지 않다.
- 따라서 현재는 FE·BE 버전 범위 기반 호환성을 확정하지 않는다. 실제 검증한 불변 커밋 또는 배포 리비전 조합만 아래 표에 기록한다.

확인 기준 커밋:

- FE: `6ba701fb3c85a8980ab090b9321f645edcfab325`
- BE: `6deb8af2f5e167cbbaf0d15ce9a025cf7c7a6227`

## SemVer 규칙

릴리스 버전을 도입하면 `MAJOR.MINOR.PATCH` 형식을 사용한다.

- `MAJOR`: 하위 호환되지 않는 변경
- `MINOR`: 하위 호환되는 기능 추가
- `PATCH`: 하위 호환되는 오류 수정

버전 범위를 기록할 때는 npm `node-semver` 관례의 의미를 따른다.

- `1.0.x`: `1.0.0` 이상 `1.1.0` 미만
- `^1.0.0`: `1.0.0` 이상 `2.0.0` 미만
- `>=1.0.0 <2.0.0`: `1.0.0` 이상 `2.0.0` 미만
- `1.0.x || 2.0.x`: 두 범위 중 하나

패키지 매니저의 범위 문법을 팀 전용 의미로 다시 정의하지 않는다.

## 검증된 호환 조합

| 검증일 | FE 릴리스·커밋 | BE 커밋·배포 리비전 | 결과 | 검증 범위 |
| --- | --- | --- | --- | --- |
| - | - | - | 미등록 | 운영 배포 조합 검증 후 추가 |

## 관리 규칙

- 호환 행은 함께 배포할 조합으로 API 계약과 주요 사용자 흐름을 검증한 뒤 추가한다.
- 브랜치 이름 대신 FE 태그와 커밋, BE 커밋 또는 불변 배포 리비전을 기록한다.
- API 요청·응답, 인증, 상태 전이, 오류 코드가 바뀌면 영향받는 조합을 다시 검증한다.
- 기존 검증 기록을 덮어쓰지 않는다. 새 조합은 새 행으로 추가하고 더 이상 지원하지 않는 조합은 결과에 종료 사유를 남긴다.
- 양쪽 저장소가 릴리스 태그 정책을 갖기 전에는 버전 범위 호환성을 기록하지 않는다.
- 같은 `MAJOR` 또는 `MINOR` 번호라는 이유만으로 호환성을 확정하지 않는다.

행 추가 형식:

```text
| YYYY-MM-DD | vX.Y.Z (`FE_COMMIT`) | `BE_COMMIT` 또는 배포 리비전 | 호환 | 인증, 온보딩, 홈 등 검증 범위 |
```

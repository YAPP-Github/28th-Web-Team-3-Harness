# 마이페이지 계정·지원 정책

- ID: POLICY-MYPAGE-001
- 상태: active
- 적용 범위: 마이페이지의 내 정보 진입, 법률 문서, 문의, 앱 버전 표시, 게스트 탈퇴

## 규칙

- 마이페이지는 인증된 게스트에게 내 정보, 이용약관, 개인정보처리방침, 문의하기, 탈퇴하기 진입점을 제공한다.
- 내 정보는 저장된 프로필 조회 화면으로 이동한다. 프로필 값의 저장·수정 규칙은 온보딩과 목표 정책의 범위로 둔다.
- 현재 사용자 조회는 유효한 access token이 필요하며 사용자 ID와 온보딩 완료 여부를 제공한다. 유효한 인증이 없으면 조회를 거절한다.
- 이용약관과 개인정보처리방침은 게스트 인증 없이 브라우저에서 열 수 있는 공개 문서로 제공한다. 고정 기준 구현의 공통 시행일은 2026년 8월 10일이다.
- 문의하기는 유효한 카카오톡 오픈채팅 주소가 설정되어 있으면 오픈채팅을 사용한다. 주소가 없거나 유효하지 않으면 개인정보 문의용 이메일을 대체 채널로 제공하고 화면에도 주소를 표시한다.
- 문의 채널은 앱 안에 새 화면으로 중첩하지 않고 현재 실행 환경이 지원하는 외부 이동 방식으로 연다.
- 앱 버전은 네이티브 앱이 유효한 버전 값을 제공한 경우에만 표시한다. 일반 브라우저에서는 표시하지 않는다.
- 게스트 탈퇴는 확인 화면에서 사용자가 명시적으로 확정한 뒤 요청한다. 확인 화면은 모든 데이터가 사라짐을 안내한다.
- 탈퇴가 완료되면 해당 게스트의 프로필·목표·저축·미션·추천 기록·혜택 저장 내역·refresh token과 계정을 함께 영구 삭제한다.
- 탈퇴 성공 후 클라이언트에 남은 사용자 데이터와 토큰을 비우고 온보딩 첫 화면으로 이동한다. 같은 기기 식별자로 다시 시작하더라도 이전 계정을 복구하지 않고 새 게스트 계정을 만든다.
- 앱 삭제는 게스트 탈퇴 요청을 실행하지 않는다. 서버 데이터 삭제가 필요하면 앱을 삭제하기 전에 마이페이지의 탈퇴 절차를 완료해야 한다.

## 불변조건

- 사용자가 확인 화면을 열거나 취소한 것만으로는 게스트 데이터가 삭제되지 않는다.
- 탈퇴 요청 처리 중에는 확인 화면을 닫거나 같은 요청을 중복 제출할 수 없다.
- 탈퇴는 한 트랜잭션에서 처리한다. 사용자 귀속 데이터 일부만 삭제된 상태를 남기지 않는다.
- 한 게스트의 탈퇴는 다른 게스트의 계정과 데이터에 영향을 주지 않는다.
- 탈퇴 완료 후 기존 access token과 refresh token은 다시 사용할 수 없다.
- 문의하기는 유효하게 구성된 오픈채팅 또는 이메일 중 하나의 경로를 제공한다.

## 예외

- 오픈채팅 주소가 비어 있거나 HTTPS가 아니거나 카카오 오픈채팅 호스트가 아니거나 URL로 해석할 수 없으면 이메일 채널로 전환한다.
- 네이티브 앱 버전을 읽지 못하거나 값이 `unknown`이면 버전 행 전체를 숨긴다. 나머지 마이페이지 기능은 계속 제공한다.
- 탈퇴 요청이 실패하면 확인 화면을 유지하고 실패 안내를 표시한다. 사용자는 처리 중 상태가 끝난 뒤 취소하거나 다시 시도할 수 있다.
- 서버 탈퇴 성공 후 네이티브 토큰 정리가 실패해도 서버의 삭제 결과를 되돌리지 않으며 온보딩 첫 화면으로 이동한다.
